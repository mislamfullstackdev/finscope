# User Entity Design

## 1. Overview

### Entity Name

`User`

### Purpose

The `User` entity represents a registered user account in the FinScope application.

It maps to the `users` database table and provides the Java object representation used by the application layer.

---

# 2. Entity Mapping

| Java Entity | Database Table |
| ----------- | -------------- |
| User        | users          |

Mapping:

```java
@Entity
@Table(name = "users")
public class User {
}
```

---

# 3. Package Location

```
src/main/java/com/finscope/user/entity/User.java
```

---

# 4. Entity Fields

| Field     | Java Type     | Database Column | Description                 |
| --------- | ------------- | --------------- | --------------------------- |
| id        | Long          | id              | Unique user identifier      |
| email     | String        | email           | User login email            |
| password  | String        | password        | Encrypted user password     |
| createdAt | LocalDateTime | created_at      | Account creation timestamp  |
| updatedAt | LocalDateTime | updated_at      | Last modification timestamp |

---

# 5. Field Design Details

## id

Java:

```java
private Long id;
```

Database:

```sql
id BIGSERIAL PRIMARY KEY
```

Rules:

* Primary key
* Automatically generated by database
* Immutable after creation

JPA mapping:

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

---

## email

Java:

```java
private String email;
```

Database:

```sql
email VARCHAR(255)
```

Rules:

* Required
* Unique
* Used for authentication

JPA mapping:

```java
@Column(nullable = false, unique = true)
private String email;
```

---

## password

Java:

```java
private String password;
```

Database:

```sql
password VARCHAR(255)
```

Rules:

* Required
* Must store encrypted password only
* Never store plain text password

Example:

```
$2a$10$N9qo8uLOickgx2ZMRZoMye...
```

JPA mapping:

```java
@Column(nullable = false)
private String password;
```

---

## createdAt

Java:

```java
private LocalDateTime createdAt;
```

Database:

```sql
created_at TIMESTAMP
```

Purpose:

Stores when the account was created.

Example:

```
2026-07-13T17:00:00
```

JPA mapping:

```java
@Column(name = "created_at", nullable = false, updatable = false)
private LocalDateTime createdAt;
```

Behavior:

* Set when user is created
* Cannot be modified later

---

## updatedAt

Java:

```java
private LocalDateTime updatedAt;
```

Database:

```sql
updated_at TIMESTAMP
```

Purpose:

Stores the latest modification time.

Example:

```
2026-07-14T10:30:00
```

JPA mapping:

```java
@Column(name = "updated_at", nullable = false)
private LocalDateTime updatedAt;
```

Behavior:

* Updated whenever user data changes

---

# 6. Entity Lifecycle

## Creating User

Flow:

```
New User Object
        |

        |
        ↓
```

---

## Updating User

Flow:

```
Existing User
        |
        ↓
Modify data
        |
        ↓
updatedAt changes
        |
        ↓
Save changes
```

# 9. Design Decisions

## Why use Long instead of Integer?

Because FinScope may grow significantly in the future.

Example:

```java
Long id
```

supports a much larger range than:

```java
Integer id
```

---

## Why use LocalDateTime?

Java:

```java
LocalDateTime
```

maps naturally to PostgreSQL:

```sql
TIMESTAMP
```

and avoids timezone conversion issues inside the application.

---

## Why not include username?

Current requirement:

* Email-based authentication

Username can be added later if required.
